# Lumen Bank (fictional): permissions

Simulated permissions: UX only, not security. Services enforce them with
`session.assert`, so a forbidden action fails even when the UI is bypassed.

## Record-level rules

<!-- protoyard:generated:rules -->
- `transfers:create`
<!-- /protoyard:generated:rules -->

- `transfers:create`: for the `member` role, allows a transfer only when
  the resource's `amountCents` is at most 50,000 (`MEMBER_TRANSFER_LIMIT_CENTS`,
  $500). Other roles, and checks made without a resource, pass the rule (the
  viewer is already denied by the capability matrix). `services.transfer`
  passes `{ amountCents }`; `simulatePayroll` asserts without a resource, so
  the cap does not apply to simulated deposits. The UI explains a denial as
  "Above your limit".

`beneficiaries:manage` and `accounts:manage` are not granted to any role by
name, so only `owner` (through `*`) can add or remove payees and freeze,
unfreeze or reactivate accounts. `accounts:read` is granted to every role but
is not checked anywhere: reads are never denied.
